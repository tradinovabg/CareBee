# CareBee — семейный дневник ухода

Next.js 16, React 19, TypeScript; мобильная страница в сине-голубой гамме. Диктовка по-русски через настоящий Web Speech API, ручной ввод, проверка текста, явное сохранение, редактирование/удаление, экспорт `.txt`. Показатели остаются обычным текстом; медицинских рекомендаций нет. Автоматическая пунктуация не добавляется.

## Запуск и публикация

Node.js 24:

```sh
npm ci
npm test
npm run typecheck
npm run build
npm start
```

Разработка: `npm run dev`. Сервер слушает порт 3000. Используйте существующий checkout `/workspace/CareBee`, отдельный worktree не нужен. Проект Vercel `care-bee` автоматически публикуется из `main` репозитория `tradinovabg/CareBee`; Vercel CLI не используется. После изменения серверных переменных нужен Redeploy в панели Vercel.

## Данные и каналы

- Дневник: localStorage `carebee.diary.v1`. Профили: `carebee.recipients.v1`. На другом телефоне или другом домене это отдельные данные. Очистка данных сайта может удалить записи; в приватном режиме хранение временное. Экспортируйте копию.
- До «Сохранить» или завершения подтверждённого отсчёта черновик не сохраняется. После отсчёта запись сначала сохраняется локально, затем выполняется отправка.
- Профиль содержит имя, алиасы, запасной номер WhatsApp, основной канал (WhatsApp или Telegram), основной профиль, подключённый chat id и ключ разрешения отправки. Номер международный, с `+`.
- Обращение распознаётся по краям диктовки с учётом регистра, знаков, `ё/е` и распространённых падежных окончаний. Неоднозначное имя не удаляется; нужен ручной выбор. Для нерегулярных форм добавляйте алиасы.
- WhatsApp: пятисекундное подтверждение, затем `wa.me` с `encodeURIComponent(text)`. Последнее подтверждение делается в мессенджере; CareBee не знает, отправлено ли сообщение. Это указано в дневнике и экспорте.
- Telegram: после тех же пяти секунд текст уходит через сервер CareBee и серверы Telegram методом Bot API `sendMessage`; дополнительных действий в Telegram при каждой отправке нет. «Доставлено» означает, что Telegram принял сообщение для чата, **а не что человек получил push или прочитал его**. Только после успеха в дневник добавляется «Отправлено: имя · время · Доставлено в Telegram»; экспорт содержит ту же оговорку.
- При ошибке запись остаётся локально без отметки доставки. «Повторить» проверяет/повторяет тот же request id, не создавая вторую запись. Если ответ сети потерялся, запрос помечается неопределённым: сначала проверьте чат. «Отправить заново» с новым id требует отдельного подтверждения из-за риска дубля. WhatsApp остаётся запасным путём через обычный отсчёт, без второй записи в дневнике.
- Сервер **не сохраняет и не логирует текст дневника**, тела сообщений и ответы Bot API. Он хранит временные данные подключения, счётчики rate limit и статусы идемпотентности без текста. Не включайте логирование тел HTTP-запросов в сторонних средствах мониторинга.

## Настройка Telegram вручную

Без настройки обычный дневник и WhatsApp продолжают работать. Никакие платные услуги автоматически не подключаются. Токены не создаются приложением и не запрашиваются в чате.

### 1. Переменные Vercel

В проекте `care-bee` → Settings → Environment Variables → **Production** задайте:

| Имя | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен вашего бота. Только сервер, никогда `NEXT_PUBLIC_*`. |
| `TELEGRAM_BOT_USERNAME` | Имя бота **без `@`**, например имя вашего собственного бота. |
| `TELEGRAM_WEBHOOK_SECRET` | Случайный секрет webhook, не менее 24 символов, только латинские буквы, цифры, `_` или `-`. Можно самостоятельно создать командой `openssl rand -hex 32`. |
| `UPSTASH_REDIS_REST_URL` | HTTPS REST URL вашей Redis-базы Upstash. |
| `UPSTASH_REDIS_REST_TOKEN` | REST token той же базы (с правами чтения и записи). |

Upstash нужен для **общих** одноразовых кодов, rate limit и защиты от повторной отправки между разными экземплярами Vercel Functions. Память одного процесса на Vercel для этого не подходит. Создайте/выберите базу на доступном **бесплатном** плане, проверьте условия и лимиты в своём аккаунте; платный план не подключайте. При отсутствии Redis или его недоступности Telegram блокируется, а не обходит защиту. База и аккаунт в ходе разработки не создавались.

После ввода значений выполните **Redeploy** текущего production-деплоя Vercel. Не добавляйте секреты в Git, URL браузера, командную строку с буквальными значениями или чат. `.env.local`, данные браузера/SQLite и `.vercel` исключены из Git и публикации. `.env.example` содержит только пустые имена.

### 2. Один раз зарегистрировать webhook

В локальном терминале с Node.js 24 создайте **игнорируемый** `.env.local` с `TELEGRAM_BOT_TOKEN` и тем же `TELEGRAM_WEBHOOK_SECRET`, который указан в Vercel. Затем из каталога проекта выполните:

```sh
node --env-file=.env.local scripts/configure-telegram.mjs https://ВАШ-РЕАЛЬНЫЙ-PRODUCTION-ДОМЕН
```

Подставьте существующий HTTPS-домен проекта; это шаблон команды, не готовая ссылка. Скрипт вызывает `setWebhook` на `/api/telegram/webhook`, задаёт `secret_token` и `allowed_updates: ["message"]`, не печатает токен и не посылает сообщения. Он заменит прежний webhook этого бота: используйте отдельного бота CareBee, а не бота другого приложения. Production webhook должен быть доступен Telegram без экрана Vercel Authentication/пароля; при включённой защите разрешите доступ только этому пути средствами вашего хостинга. Обновлять webhook при каждом деплое с тем же доменом не нужно.

### 3. Подключить человека

1. CareBee → «Получатели» → добавить/изменить профиль, указать запасной номер WhatsApp и сохранить.
2. «Подключить Telegram» выдаст одноразовую ссылку на бота. **Передайте её только нужному человеку**: первым нажавший «Старт» привяжет свой личный чат. Ссылка действует 10 минут. Отдельный секрет проверки остаётся в браузере инициатора, в ссылку он не включается.
3. Человек открывает бота и нажимает **Старт**. Оставьте страницу CareBee открытой/вернитесь в неё: она проверяет состояние примерно раз в 3 секунды и сохраняет chat id и ключ в браузере.
4. Нажмите **«Проверить связь»** — это действительно посылает фиксированное пробное сообщение. После получения выберите **Telegram основным каналом** в профиле.
5. Создайте вымышленную запись → «Отправить» → проверьте получателя за 5 секунд → дождитесь результата. Нажимать отправку в Telegram больше не нужно.

Привязка доступна только личным чатам, не группам. Бот не может начать разговор первым: человек обязан нажать Старт. При блокировке бота его нужно разблокировать и повторить подключение/проверку. При смене `TELEGRAM_BOT_TOKEN` прежние ключи подключения перестанут действовать — подключите профили заново.

## Защита и сроки хранения

- `/api/telegram/send` принимает только chat id с серверным HMAC-разрешением, выданным при подключении. Сам по себе chat id не позволяет отправлять сообщения.
- Один код связывается только с первым личным чатом атомарной Redis-операцией. Код, секрет проверки и chat id удаляются из Redis по TTL 10 минут.
- Лимит текста: **4096 UTF-16 символов**, plain text без parse_mode. Для более длинных записей сократите текст или используйте WhatsApp.
- Общие Redis-лимиты: 5 отправок/минуту в чат, 15/минуту на IP, 30/минуту на бота; создание ссылок — 5/минуту на IP и 30/минуту на бота; проверка состояния — 40/минуту на IP. Ключи IP хешируются. Без доверенного Vercel IP используется общий `unknown` bucket.
- Статусы запросов отправки без текста хранятся 24 часа. Успешный повтор с тем же id не вызывает Bot API второй раз. При сетевой неопределённости автоматического повтора нет.
- Сервер ограничивает тело запроса 40 КБ и время внешних запросов. Запросы UI проверяются по Origin; webhook — по секретному заголовку Telegram. Не используйте одного бота для посторонних сервисов. Rate limit снижает спам, но не заменяет полноценную авторизацию: публичный сервис может исчерпать общий бесплатный лимит. При расширении за пределы семьи потребуется доступ по аккаунтам/приглашениям.

## Голос и проверки

Используется настоящий `SpeechRecognition` / `webkitSpeechRecognition`, `ru-RU`; обычно нужен интернет. Аудио может передаваться сервису браузера (например, Google/Apple), о чём есть предупреждение. При отказе микрофона доступен ручной ввод. На телефоне нужен доверенный HTTPS и разрешение микрофона сайту/браузеру в ОС. Живое русское распознавание на телефоне в облачном окружении не проверено.

`npm test` использует заглушки Redis/Bot API: успех, идемпотентность, сеть, отсутствие токена/chat id, поддельное разрешение, длина, ограничения частоты, одноразовая привязка и webhook-секрет, пробное сообщение, хранение профилей, резервный WhatsApp и экспорт. Настоящие сообщения тестами **не отправляются**. Пользователь должен отдельно проверить реальные webhook/бота и получение сообщения после ввода настроек.
